MarketCore — Otimizações do Pipeline de Book

15 fixes aplicados em 2 fases • Arquivos: MarketEngine.cs, ProfitDLLProvider.cs, ProfitDLLBridge.cs, DllLatencyMonitor.cs, PregaoVivaVozUnifiedLog.cs

Fase 1 Bottlenecks estruturais — gargalos de contenção e escala
Fix 4Reduzir OperationalBookSideCap de 30.000 → 5.000perf
Engine/MarketEngine.cs
O livro armazenava até 30K ofertas por lado. Todas as operações O(n) — busca, eviction, snapshot copy — escalavam com esse N. Reduzir para 5K corta 6× o custo de cada operação linear, mantendo profundidade mais que suficiente para a tela (2.500 linhas visíveis).
Fix 5Throttle do snapshot publish: 50ms + prioridade Normalperf
Engine/MarketEngine.cs
A thread de publicação de snapshots rodava sem throttle e com prioridade AboveNormal, competindo com o processamento do book. Agora roda a cada 50ms (20 fps — mais que suficiente para UI) com prioridade Normal, liberando CPU para o consumer da fila de book.
Fix 6Backpressure PVV: skip quando fila > 500safety
Engine/MarketEngine.cs, Providers/Nelogica/DllLatencyMonitor.cs, Providers/Nelogica/ProfitDLLProvider.cs
O módulo Pregão Viva Voz (PVV) fazia I/O e processamento extra em cada evento de book, mas não parava mesmo quando a fila crescia. Adicionado BookQueueDepth no DllLatencyMonitor e check de backpressure: se a fila > 500, pula o hook PVV para o evento. Evita que o PVV amplifique o atraso quando o sistema já está sob carga.
Fix 7Cache de alias em TryResolveBookStateperf
Engine/MarketEngine.cs
Quando o ticker não era encontrado diretamente no _books, o fallback iterava todas as chaves comparando ExtrairAtivo() — O(n) por evento. Agora, na primeira resolução bem-sucedida, o alias é cacheado com _books.TryAdd(ticker, state), transformando todas as chamadas subsequentes em O(1).
Fase 2 Auditoria profunda — eliminar todo O(n) e O(n²) do hot path
Fix 8Eviction com watermark: bulk remove até 4.000perf
Engine/MarketEngine.cs
Antes, ao atingir o cap, cada insert forçava uma eviction O(n) unitária. Agora usa watermark: quando chega ao cap, remove em lote até EvictionLowWatermark (4.000), e só volta a evictar quando atingir 5.000 de novo. Reduz evictions de ~1.000/sec para ~1 a cada poucos segundos.
Fix 9MergeSideFromFullSnapshot cappedperf
Engine/MarketEngine.cs
Full snapshots podiam trazer 10K+ itens. Antes, cada um era inserido e imediatamente evicado → O(n²). Agora o incoming é limitado a OperationalBookSideCap e itens que não cabem são descartados sem eviction, eliminando o quadrático.
Fix 10TryInsertOfferAtPosition usa list.Add (O(1))perf
Engine/MarketEngine.cs
List.Insert(idx) desloca todos os elementos à direita — O(n). Como a ordem interna é irrelevante (snapshots re-ordenam por preço, PVV usa OfferId), substituído por list.Add() que é O(1) amortizado.
Fix 11TryParseOfferBookDate com cache de formatoperf
Providers/Nelogica/ProfitDLLProvider.cs
Cada evento tentava parsear a data com até 6 formatos sequenciais via DateTime.TryParseExact. Como o formato é estável durante a sessão, adicionado _lastMatchedFormatIdx volátil — tenta o último formato que funcionou primeiro. Elimina 5 tentativas falhadas por evento nos ~98% dos casos.
Fix 12TryParseOfferBookDateBytes com stackallocperf
Providers/Nelogica/ProfitDLLProvider.cs
Versão bytes do parser usava Encoding.ASCII.GetString() alocando uma string no heap por evento. Substituído por Span<char> chars = stackalloc char[length] + TryParseExact com span — zero alocação de heap, menos pressão no GC.
Fix 13SwapRemoveAt — remoção O(1) de listasperf
Engine/MarketEngine.cs
List.RemoveAt(idx) desloca todos os elementos — O(n). SwapRemoveAt copia o último elemento para a posição removida e faz RemoveAt(last) — O(1). Aplicado em case 2 (delete) e case 3 (deleteFrom). Case 2 agora prioriza OfferId lookup ao invés de posição para evitar remoção errada em lista desordenada.
Fix 14TryPriceToDecimal simplificadoperf
Providers/Nelogica/ProfitDLLProvider.cs
Usava try-catch com Convert.ToDecimal + Math.Round. Em hot path com 2.000 calls/sec, try-catch (quando lança) é extremamente caro. Substituído por validação direta + cast (decimal)price sem try-catch e sem Round desnecessário.
Fix 15Buffered callback logging (PVV)I/O
MarketCore.WPF/Services/PregaoVivaVoz/ProfitDLLBridge.cs, PregaoVivaVozUnifiedLog.cs
Cada callback fazia File.AppendAllText — open/write/close/flush em disco, 2× por evento (callback log + unified log). Com 200+ callbacks/sec no PVV ativo, era ~400 I/O ops/sec no thread de processamento. Substituído por ConcurrentQueue + flush periódico (a cada 500ms ou 100 linhas). Adicionado AppendBatch no unified log para escrita em lote.
